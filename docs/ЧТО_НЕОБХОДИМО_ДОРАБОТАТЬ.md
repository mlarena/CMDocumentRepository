## ПРИОРИТЕТ 0: КРИТИЧЕСКИЕ БАГИ (блокируют работу)

### 0.1 Ошибка уникальности версий документов 🔴 КРИТИЧНО

**Проблема:** При загрузке 3-й версии документа возникает ошибка:
```
Npgsql.PostgresException: 23505: duplicate key value violates unique constraint 
"IX_DocumentVersions_DocumentId_VersionNumber"
```

**Причина:** В `UpdateDocumentCommandHandler` (строки 176-178) версия вычисляется как:
```csharp
var latestVersion = await _versionRepository.GetLatestAsync(document.Id);
var newVersionNumber = latestVersion != null
    ? Math.Floor(latestVersion.VersionNumber) + 0.1m
    : 1.1m;
```

Проблемы:
- Нет проверки на существование версии с таким номером перед вставкой
- Нет поддержки МАЖОРНЫХ версий (1.0 → 2.0 → 3.0) — только МИНОРНЫЕ (1.1, 1.2, 2.1)
- При повторной загрузке файла с тем же названием может возникнуть дубликат

**Решение:**
1. Добавить поле `VersionType` (Major/Minor) в `DocumentVersion`
2. Добавить поле `IsMajorVersion` в `UpdateDocumentCommand` и `UpdateDocumentDto`
3. Добавить проверку существования версии перед вставкой
4. Реализовать логику: при мажорной версии — `floor(version) + 1`, при минорной — `floor(version) + 0.1`
5. Добавить транзакцию для атомарности операции

**Файлы:** `Domain/Entities/DocumentVersion.cs`, `Application/Commands/DocumentCommands.cs`, `Application/Commands/DocumentCommandHandlers.cs`, `Infrastructure/Configurations/DocumentVersionConfiguration.cs`

### 0.2 Отсутствует SearchVector для FTS поиска 🔴 КРИТИЧНО

**Проблема:** `SearchService.FullTextSearchAsync()` использует поле `SearchVector`, которое отсутствует в сущности `Document`. PostgreSQL FTS не может работать без этого поля.

**Причина:** В `Document.cs` нет свойства `SearchVector`, в `DocumentConfiguration.cs` нет настройки индексаGIN для полнотекстового поиска.

**Решение:**
1. Добавить поле `public string? SearchVector { get; set; }` в `Document.cs`
2. Настроить триггер PostgreSQL для автоматического обновления SearchVector при изменении Title/Description
3. Создать миграцию для добавления GIN индекса
4. Обновить `SearchService.BuildTsQuery()` — текущий SQL использует `{0}` дважды без параметризации

**Файлы:** `Domain/Entities/Document.cs`, `Infrastructure/Configurations/DocumentConfiguration.cs`, `Infrastructure/Services/SearchService.cs`, `Infrastructure/Data/AppDbContext.cs`

---

### 0.3 JSONB Metadata не маппится (нет ValueConverter) 🟡 СРЕДНЕ

**Проблема:** `Document.Metadata` настроен как `HasColumnType("jsonb")`, но EF Core не может автоматически маппить тип `JsonDocument?` без ValueConverter.

**Причина:** В `DocumentConfiguration.cs` строка 46:
```csharp
builder.Property(d => d.Metadata).HasColumnType("jsonb");
```
Отсутствует `.HasConversion()`.

**Решение:**
1. Добавить ValueConverter для JsonDocument ↔ string
2. Добавить поле `Metadata` в `UpdateDocumentCommand`, `UpdateDocumentDto`, `DocumentDto`
3. Добавить UI для редактирования метаданных на странице редактирования документа

**Файлы:** `Infrastructure/Configurations/DocumentConfiguration.cs`, `Application/DTOs/DocumentDto.cs`, `Application/Commands/DocumentCommands.cs`

---

### 0.4 Нет возможности выбрать согласующего из UI 🟡 СРЕДНЕ

**Причина:** Контроллер `ApprovalController.SendForApproval()` принимает `List<Guid> approverIds`, но View не содержит UI для выбора пользователей.

**Решение:**

3. Реализовать AJAX-отправку формы выбора

**Файлы:** `Views/Document/Details.cshtml`, `Controllers/DocumentController.cs`, `wwwroot/js/site.js`

### 1.1 Блокировка после неудачных попыток входа 🔴 КРИТИЧНО

**Проблема:** ТЗ требует: «Блокировка после 5 неудачных попыток (15 мин)», но в коде реализована только проверка `IsLocked`/`LockedUntil` без отслеживания попыток.

**Причина:** В `User.cs` нет полей `LoginAttempts` и `LastLoginAttemptAt`. В `LoginCommandHandler` нет логики инкремента попыток.

**Решение:**
1. Добавить поля `public int LoginAttempts { get; set; }` и `public DateTime? LastLoginAttemptAt { get; set; }` в `User.cs`
2. В `LoginCommandHandler`: при неудачном входе — инкрементировать `LoginAttempts`, при достижении 5 — установить `IsLocked = true`, `LockedUntil = DateTime.UtcNow.AddMinutes(15)`
3. При успешном входе — сбросить `LoginAttempts = 0`
4. При разблокировке — сбросить `LoginAttempts = 0`
5. Создать миграцию

**Файлы:** `Domain/Entities/User.cs`, `Application/Commands/AuthCommandHandlers.cs`, `Infrastructure/Migrations/`

### 2.2 Устранить N+1 запросы 🔴 КРИТИЧНО

**Проблема:** В `GetAllDocumentsQueryHandler`, `SearchDocumentsQueryHandler`, `GetMyDocumentsQueryHandler` — foreach с отдельными запросами для Category, Type, Creator.

**Пример (GetAllDocumentsQueryHandler, строки 175-203):**
```csharp
foreach (var doc in docs)
{
    var category = await _categoryRepository.GetByIdAsync(doc.CategoryId);
    var type = await _typeRepository.GetByIdAsync(doc.DocumentTypeId);
    var creator = await _userRepository.GetByIdAsync(doc.CreatedBy);
    // ... маппинг
}
```

**Решение:**
1. Загрузить все категории, типы и пользователей одним запросом
2. Создать словари `Dictionary<Guid, Category>`, `Dictionary<Guid, DocumentType>`, `Dictionary<Guid, User>`
3. Маппить из словарей

**Файлы:** `Application/Queries/QueryHandlers.cs`
