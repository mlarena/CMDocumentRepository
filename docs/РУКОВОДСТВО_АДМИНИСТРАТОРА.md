# Руководство администратора CMDocumentRepository

## Требования к системе

| Компонент | Требование |
|-----------|------------|
| ОС | Debian 12 / Ubuntu 22.04 LTS |
| CPU | 4 ядра |
| RAM | 8 ГБ (минимум 4 ГБ) |
| Диск | 100 ГБ SSD |
| PostgreSQL | 15+ |
| .NET Runtime | 10.0 |

## Установка

### 1. Установка зависимостей

```bash
sudo apt-get update
sudo apt-get install -y dotnet-sdk-10.0 postgresql nginx
```

### 2. Создание базы данных

```bash
sudo -u postgres psql -c "CREATE DATABASE CMDocumentRepository;"
sudo -u postgres psql -c "CREATE USER docuser WITH PASSWORD 'your_password';"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE CMDocumentRepository TO docuser;"
```

### 3. Настройка строки подключения

Отредактируйте файл `appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Database=CMDocumentRepository;Username=docuser;Password=your_password"
  }
}
```

### 4. Сборка и развёртывание

```bash
dotnet publish -c Release -o /var/www/document-system
```

### 5. Настройка systemd сервиса

Создайте файл `/etc/systemd/system/document-system.service`:

```ini
[Unit]
Description=CMDocumentRepository
After=network.target

[Service]
WorkingDirectory=/var/www/document-system
ExecStart=/usr/bin/dotnet /var/www/document-system/CMDocumentRepository.Presentation.dll
Restart=always
RestartSec=10
User=www-data
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=DOTNET_PRINT_TELEMETRY_MESSAGE=false

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable document-system
sudo systemctl start document-system
```

### 6. Настройка Nginx

Создайте файл `/etc/nginx/sites-available/document-system`:

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://localhost:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection keep-alive;
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/document-system /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

## Управление пользователями

### Создание пользователя

1. Войдите как SuperAdmin (su / 1234567890)
2. Перейдите в "Администрирование" -> "Пользователи"
3. Нажмите "Создать пользователя"
4. Заполните данные и выберите роль

### Роли

| Роль | Описание |
|------|----------|
| SuperAdmin | Полный доступ ко всем функциям |
| Admin | Управление пользователями и настройками |
| Manager | Создание и согласование документов |
| User | Создание и просмотр документов |
| Auditor | Только просмотр |
| Guest | Ограниченный просмотр |

### Блокировка пользователя

1. Откройте профиль пользователя
2. Нажмите "Заблокировать"
3. Укажите время блокировки (по умолчанию 15 минут)

## Резервное копирование

### Создание бэкапа

```bash
#!/bin/bash
BACKUP_DIR="/backups/$(date +%Y%m%d)"
mkdir -p $BACKUP_DIR

# Бэкап БД
pg_dump CMDocumentRepository > $BACKUP_DIR/CMDocumentRepository.sql

# Бэкап файлов
tar -czf $BACKUP_DIR/uploads.tar.gz /var/www/document-system/uploads/

# Очистка старых бэкапов (7 дней)
find /backups -type d -mtime +7 -exec rm -rf {} \;
```

### Автоматический бэкап (cron)

```bash
0 2 * * * /path/to/backup.sh
```

## Безопасность

### Рекомендации

1. Измените пароль суперпользователя после установки
2. Настройте HTTPS (Let's Encrypt)
3. Ограничьте доступ к админ-панели по IP
4. Регулярно обновляйте зависимости
5. Настройте брандмауэр (UFW)

### Настройка HTTPS

```bash
sudo apt-get install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

## Решение проблем

### Сервис не запускается

1. Проверьте логи: `sudo journalctl -u document-system -n 100`
2. Убедитесь, что PostgreSQL запущен
3. Проверьте строку подключения в `appsettings.json`

### Ошибка подключения к БД

1. Проверьте, что PostgreSQL доступен: `pg_isready -h localhost`
2. Проверьте права пользователя БД
3. Проверьте firewall
