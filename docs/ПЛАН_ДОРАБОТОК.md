### 0.1 Версионирование документов — ошибка уникальности 🔴 КРИТИЧНО

**Симптом:** При загрузке 3-й версии документа:
```
Npgsql.PostgresException: 23505: duplicate key value violates unique constraint 
"IX_DocumentVersions_DocumentId_VersionNumber"
```

**Причина:** `UpdateDocumentCommandHandler` вычисляет версию без проверки существования:
```csharp
var newVersionNumber = latestVersion != null
    ? Math.Floor(latestVersion.VersionNumber) + 0.1m  // Всегда +0.1, без проверки
    : 1.1m;
```

**Детализированный план исправления:**

#### Шаг 1: Расширить доменную модель
- Добавить `public bool IsMajorVersion { get; set; }` в `DocumentVersion`
- Добавить `public string? MajorVersionComment { get; set; }` (комментарий при мажорной версии)
- Создать миграцию `AddDocumentVersionMajorFlag`

**Файлы:** `Domain/Entities/DocumentVersion.cs`, `Infrastructure/Migrations/`

#### Шаг 2: Обновить команду и DTO
- Добавить `public bool IsMajorVersion { get; init; }` в `UpdateDocumentCommand`
- Добавить `public bool IsMajorVersion { get; init; }` в `UpdateDocumentDto`

**Файлы:** `Application/Commands/DocumentCommands.cs`, `Application/DTOs/DocumentDto.cs`

#### Шаг 3: Переписать логику вычисления версии
```csharp
// Новая логика в UpdateDocumentCommandHandler:
if (request.IsMajorVersion)
{
    // Мажорная версия: 1.0 → 2.0 → 3.0
    newVersionNumber = latestVersion != null 
        ? Math.Floor(latestVersion.VersionNumber) + 1.0m 
        : 2.0m;
}
else
{
    // Минорная версия: 1.0 → 1.1 → 1.2 → 2.0
    var currentFloor = Math.Floor(latestVersion.VersionNumber);
    var currentMinor = latestVersion.VersionNumber - currentFloor;
    newVersionNumber = currentFloor + currentMinor + 0.1m;
}
```

#### Шаг 4: Добавить проверку и транзакцию
- Обернуть создание версии в транзакцию
- Ловить `DbUpdateException` с сообщением о дубликате

#### Шаг 5: Обновить UI
- Добавить чекбокс «Создать мажорную версию (1.0 → 2.0)» на страницу `Edit.cshtml`
